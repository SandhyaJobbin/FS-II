<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Candidate/recruiter mail inbox → HTML render engine | Recipient email clients render HTML with varying restrictions (Outlook/Word engine is the strictest — no flexbox, limited CSS). |
| Candidate-controlled name/email → rendered email HTML | XSS risk on any user-controlled string interpolated into HTML — mitigate via escape() helper. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-20 | Tampering | Injected `<script>` in candidate name executes when recruiter opens email (XSS) | high | mitigate | Task 2 escape() helper applied to every user-string interpolation; Task 1 test #4 asserts `<script>` renders escaped in the output. |
| T-13-21 | Information Disclosure | Recruiter-only violation summary leaks to candidate email (D-02 recruiter-only divergence broken) | high | mitigate | Task 1 test #6 explicitly asserts candidate email does NOT contain violation/integrity content; buildCandidateEmail passes `includeViolations: false` to buildReportHtml. |
| T-13-22 | Denial of Service | Outlook Word-engine collapses the layout, making the report unreadable | medium | mitigate | 13-RESEARCH.md Pitfall 4 addressed: table-only layout, no flexbox/grid, inline styles, 640px max-width. Task 2 verification includes a manual Outlook send in plan 13-09 Wave 3 live-verify. |
| T-13-23 | Repudiation | Plain-text fallback empty (current state) means text-only email clients get nothing | medium | mitigate | Task 2 populates plainBody with score + traits + tier + narrative; MailApp.sendEmail third arg no longer empty string. |
| T-13-SC | Tampering | npm/pip/cargo installs | low | accept | No new dependencies in this plan. |
