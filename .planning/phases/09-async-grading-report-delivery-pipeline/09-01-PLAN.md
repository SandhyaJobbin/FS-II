<objective>
Split `handleSubmitAnswers` in `backend/Code.gs` from a synchronous grading handler into a fast-enqueue handler, and give it somewhere durable to enqueue to: a new `PendingGrading` sheet, lazily created inside the existing `initSheets()` convention. Also make the one existing report-readiness gate (`handleGetAttemptReport`) recognize the new post-enqueue terminal states so admins don't lose access to reports the moment submissions stop landing on `"submitted"`.

Purpose: This is the request-path half of Phase 9's async pipeline (ROADMAP Phase 9 Success Criteria #1 and #2) -- it is what makes `doPost` fast and gives the async worker (plan 09-02) a durable queue to drain. Per D-01 through D-16 (09-CONTEXT.md), the actual grading/email logic is deliberately NOT written here -- it is relocated verbatim into `backend/AsyncGrading.gs` by the parallel plan 09-02.
Output: `backend/Code.gs` with a 4th lazily-created sheet (`PendingGrading`), a fast-enqueue `handleSubmitAnswers`, and a backward-compatible `handleGetAttemptReport` gate.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|--------------|------------------|
| T-09-02a | Denial of Service | `doPost(submitAnswers)` | high | mitigate | Preserve the existing `attemptRow[5] !== "active"` idempotency guard byte-for-byte -- a retried/duplicate request for the same attempt is rejected before it can append a second PendingGrading row or consume MailApp quota twice downstream (plan 09-02) |
| T-09-03 | Tampering / Repudiation | `doPost(submitAnswers)` | medium | mitigate | Same idempotency guard prevents duplicate grading/emailing from a replayed request; `Status` transitions strictly forward (`active` -> `pending_grading` -> ...), never backward |
| T-09-06 | Tampering | `PendingGrading` sheet (direct Sheet edit) | low | accept | Sheet-level access is restricted to the Apps Script project owner/editors -- the same trust boundary already accepted for `Attempts`/`Responses`/`IntegrityLogs`; this phase introduces no new exposure |
