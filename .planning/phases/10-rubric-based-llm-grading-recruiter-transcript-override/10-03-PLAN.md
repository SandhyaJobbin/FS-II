<objective>
Add the two recruiter-facing backend endpoints that surface Wave 1's transcripts and let recruiters flip a verdict with an audit trail. `handleGetAttemptTranscript` is the read side; `handleOverrideVerdict` is the write side, wrapped in `LockService` and forced to re-aggregate all score columns using the `effectiveVerdict` helper from plan 10-02 so the override becomes the new source of truth without diverging from the initial-grading policy.

Purpose: This is the Wave 1 endpoint layer for Success Criteria 3 (recruiter transcript UI has data to render — GRADE-08) and Success Criteria 3's second half (attributable override — GRADE-09). It depends on plan 10-02 for `effectiveVerdict()` and the `GradingTranscripts` sheet. It deliberately does NOT touch the frontend — that is plan 10-05, executed in Wave 2 after all backend endpoints exist. Rationale: keeping backend and frontend in separate waves means the UI plan can consume a stable API surface without re-planning if backend endpoint signatures shift late.

Output: `backend/Code.gs` gains two new handler functions wired to two new action strings in the doPost/doGet router.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin browser -> doPost(overrideVerdict) | Token in POST body (NOT query string); untrusted attemptId/questionId/newVerdict/token cross this boundary |
| Admin browser -> doGet(getAttemptTranscript) | Token in query string (per project GET convention); returns rationale text which may echo prompt-injection attempts from candidate answers |
| handleOverrideVerdict -> GradingTranscripts + Attempts write | Serialized by LockService.tryLock(10000ms); competes with processGradingQueue's tryLock(5000ms) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-03a | Spoofing / Elevation of Privilege | handleOverrideVerdict without token | high | mitigate | `checkAdminAuth(token)` runs before any sheet access. Same pattern as handleAdminResetAttempt. Bad-token property test asserted by plan 10-04 sync-check. |
| T-10-03b | Tampering / Concurrency | Concurrent override races processGradingQueue | high | mitigate | LockService.getScriptLock().tryLock(10000ms) — longer than processGradingQueue's 5000ms so the override yields to an in-flight drain rather than colliding at the sheet write. Release in `finally`. RESEARCH.md Pattern 3. |
| T-10-03c | Repudiation | Fake override attribution / audit spoofing | medium | mitigate | OverrideTokenHash is SHA-256 hex of the token — one shared token means all recruiters share a hash (documented A5 limitation), but no one can forge an override without knowing the token. Timestamp is ISO 8601 UTC. Sheet is append-safe by convention. |
| T-10-03d | Information Disclosure | Rationale text exposed to admin panel may contain PII the candidate wrote | medium | accept | Recruiter role has authorized access to candidate submissions; rationale is only shown INSIDE the token-gated admin modal (never sent to the candidate — A6). Prompt-injection markers may appear in rationale; Pitfall 4 note documents that as a monitoring signal. |
| T-10-03e | Tampering | Plaintext ADMIN_TOKEN written to a sheet cell (accidental) | high | mitigate | Task 2 explicitly stores `tokenHash` (hex of SHA-256), never `token`. Plan 10-04 sync-check adds a property test asserting `OverrideTokenHash !== ADMIN_TOKEN` (invariant #4 in RESEARCH.md Validation Architecture). |
| T-10-03f | Denial of Service | 10000ms lock hold times out normal grading drains | medium | accept | Re-aggregation for one attempt is ~50 questions × O(1) sheet reads — well under 10 seconds in practice. If a runaway override ever holds 10s+, processGradingQueue's own tryLock(5000) will fail and be retried on the next 5-minute trigger fire (existing Phase 9 behavior). Plan 10-07 measures this live. |
| T-10-03-SC | Tampering | npm/pip/cargo installs | n/a | n/a | Plan installs zero packages — Package Legitimacy Gate not applicable. |
