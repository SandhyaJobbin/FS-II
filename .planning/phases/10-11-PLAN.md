# Implementation Plan: Phases 10 & 11

This document outlines the detailed execution steps, data schemas, and UI designs for implementing Phase 10 and Phase 11.

---

## Phase 10: Rubric-Based LLM Grading + Recruiter Transcript & Override

**Goal**: Upgrade the async grading pipeline to use structured rubric-based LLM grading, persist transcripts/rationales, provide recruiter override UI, and update candidate-facing copy.

### Wave 1: Backend Rubrics, Structured Output, and Persistence

#### 1. Rubric Configuration in `QUESTIONS` Database (`Code.gs`)
For each `open_text` and `hybrid` type question, we add a structured `rubric` property inside the embedded `QUESTIONS` array in `Code.gs`.

```javascript
{
  id: "ENG_ME_001",
  bank: "english",
  section: "macro",
  response_type: "open_text",
  difficulty_tier: "complex",
  stem: "Analyze this email and rewrite it with a professional tone...",
  rubric: {
    version: 1,
    criteria: [
      { name: "Grammar & Mechanics", weight: 0.3, description: "Evaluates correct syntax, punctuation, spelling, and paragraph structure." },
      { name: "Professional Tone", weight: 0.3, description: "Evaluates polite, objective, helpful, and non-defensive language appropriate for customer support." },
      { name: "Instruction Adherence", weight: 0.4, description: "Checks if the candidate addressed all constraints mentioned in the email prompt." }
    ]
  }
}
```

#### 2. Structured Gemini Rubric Grading (`AsyncGrading.gs`)
We replace the ad-hoc `evaluateOpenTextBatch` with a structured rubric-evaluator that utilizes Gemini's `responseSchema` to enforce a standard JSON payload return.

```javascript
function evaluateWithRubric(gradingRequests) {
  // Configures the request schema for Gemini API:
  const responseSchema = {
    type: "object",
    properties: {
      verdict: { type: "string", enum: ["correct", "incorrect", "ungraded"] },
      criteriaMet: {
        type: "array",
        items: {
          type: "object",
          properties: {
            criterionName: { type: "string" },
            met: { type: "boolean" },
            score: { type: "number" } // 0.0 to 1.0 representation
          }
        }
      },
      rationale: { type: "string" }
    },
    required: ["verdict", "criteriaMet", "rationale"]
  };
  
  // Call Gemini using this schema. Any network/parsing failure defaults to "ungraded" verdict.
}
```

#### 3. GradingTranscripts Storage Sheet
A new sheet named `GradingTranscripts` will persist transcripts and rationales per open-text response.

* **Schema**: `AttemptID` | `QuestionID` | `RubricVersion` | `Verdict` | `CriteriaMetJSON` | `Rationale` | `OverrideVerdict` | `OverrideAt` | `OverrideTokenHash`

#### 4. Surfacing Ungraded Status in Report Data
We add an `ungradedCount` metric to report summaries and client payloads. If `ungradedCount > 0`, the candidate-facing UI shows a notice that scores are pending review, and recruiters are flagged to complete manual grading.

## Phase 11: Recruiter Analytics Dashboard

**Goal**: Implement an on-demand aggregation dashboard in the admin panel covering score distributions, question difficulty, cheat warning correlations, and fraud bias indicators.

### Wave 1: Backend Aggregation and Tagging

#### 1. Analytics Aggregation Endpoint (`Code.gs`)
Add a new administrative endpoint `handleAdminAnalytics(token)` that returns aggregated metrics computed on-the-fly.

* **Aggregated Metrics**:
  * **Score Trend**: Average scores grouped by cohort/week.
  * **Question Stats**: Pass rate (%) and total attempts per Question ID.
  * **Violation Correlation**: Average scores grouped by violation count buckets (`0`, `1-2`, `3+`).
  * **Bias-Direction Indicator**: Distribution of candidate errors matching error bias profiles.

#### 2. Bias-Direction Tagging
We add a tag to MCQ questions in the Attention and Critical Thinking banks to support the bias-direction indicator:

* `error_direction`: `"false_positive" | "false_negative" | null`
  * **False Positive**: Incorrect choice that incorrectly flags an authentic account/listing as fraudulent.
  * **False Negative**: Incorrect choice that misses actual fraud.

---

### Wave 2: Frontend Analytics Dashboard

#### 1. Toggleable Tab Layout (`admin/page.tsx`)
Split the admin panel into two view modes:
* **Candidates**: The standard candidate lookup list.
* **Analytics**: The new metrics dashboard.

#### 2. Analytics Visualizations (`AnalyticsDashboard.tsx`)
* **Score Trend Chart**: A lightweight SVG line chart displaying average scores over time with minimum and maximum range bands.
* **Question Performance Grid**: A sortable table listing all questions sorted by pass rate to let recruiters review bad/outdated content.
* **Violation Correlation**: Grouped bar visualization showing how violation count correlates with performance.
* **Bias-Direction Radar/Donut**: Shows whether the applicant pool skews towards over-flagging or under-flagging.
* **Low-N Fallback**: If total attempts are `< 20`, displays a clean fallback illustration: *"Not enough data yet. Analytics will unlock after 20 completed attempts."*
